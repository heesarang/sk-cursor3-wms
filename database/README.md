# 데이터베이스 실습

요구사항을 분석하여 DB 모델을 설계하고 필요한 SQL과 데이터 사전을 작성합니다.

1. 기본 PRD와 DB Rule을 읽고 모델을 설계합니다.
2. 검토한 DDL을 `schemas/wms_ddl.sql`로 작성하고 `tools/std_check.sql`로 형식을 점검합니다. 업무 규칙(M:N, 수량 CHECK, 상태 코드)은 PRD와 대조해 직접 리뷰합니다.
3. 기준 모델 확정 후 데이터 사전을 갱신합니다.
4. 동일 모델 기준으로 시드·검증·초기화 SQL을 작성합니다.
5. 변경 요청 단계에서는 마이그레이션과 전체 DDL·정의서를 함께 갱신합니다.

## 폴더

- init: 롤·권한 (`00_roles.sql`, 관리자가 1회 실행)

- schemas: 확정할 전체 DDL
- seeds: 모델 확정 후 작성하는 코드·마스터·샘플 데이터
- migrations: 기준 모델 확정 이후의 변경 이력
- tools: `std_check.sql`(표준 자동 점검, 위반 0 = PASS), `reset_schema.sql`(기준 모델 확정 전 초기화). 적용 확인 SQL은 실습에서 작성
- docs: ERD·테이블 정의서
- reports: 로컬 검증 결과(커밋 제외)

## 데이터 초기화

데이터 초기화 도구는 실습 모델의 테이블과 외래 키 관계에 맞춰 작성합니다.

- 교육용 DB·스키마·대상 테이블 명시
- 트랜잭션 및 오류 시 중단
- FK 참조 순서 또는 대상 테이블 일괄 지정, 무분별한 CASCADE 금지
- 업무 데이터만 지울지 기준정보까지 지울지 구분
- 시퀀스 초기화 여부와 시드 재적재 순서 명시
- 명시적 실행 확인과 실행 후 검증

실행 전 접속 DB·대상 테이블·삭제 범위를 확인하고, 운영 DB에서는 실행하지 않습니다.
