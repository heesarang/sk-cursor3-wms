## 1. 배경 및 목적

### 1.1 운영 요청 (원문)

> 1. 재고를 관리하고 싶어  
> 2. 입고를 하면 재고가 늘어나고  
> 3. 출고를 하면 재고가 줄어들고  
> 4. 재고 이력을 볼 수 있는 재고 메뉴 생성이 필요해  
> 5. 기본재고는 등록된 아이템들에 대해 기본 1000으로 해서 만들어줘

### 1.2 As-Is

| 영역 | 현재 | 문제 |
|------|------|------|
| 데이터 | 재고 잔량·이력 테이블 없음 | 실물 수량을 시스템에 둘 수 없음 |
| 입고 확정 | `20→90` 시 상태·이력만 변경 | 재고가 늘지 않음 |
| 출고 확정 | `20→90` 시 상태·이력만 변경 | 재고가 줄지 않음 |
| UI | 네비에 재고 메뉴 없음 | 잔량·이력을 한곳에서 볼 수 없음 |
| 초기값 | — | 교육·운영 시작 시 빈 재고면 출고 연습이 어려움 |

### 1.3 To-Be

- 센터×SKU 단위로 **가용 재고**를 관리한다.
- **입고 확정** 시 해당 라인 수량만큼 재고가 **증가**하고, **출고 확정** 시 **감소**한다.
- 상단 네비에 **재고** 메뉴를 두어 잔량 조회와 **재고 이력**을 본다.
- 활성 센터×활성 품목(등록된 아이템)마다 **기본 재고 1000**으로 초기화한다.

### 1.4 범위

| 포함 | 제외 |
|------|------|
| 재고 잔량·재고 이력 테이블(마이그레이션) | 로트/유통기한/로케이션 |
| 입고 확정(`20→90`) 시 재고 증가 | 재고 실사·수동 조정 화면 (2차) |
| 출고 확정(`20→90`) 시 재고 감소·부족 시 거부 | 출고 **등록** 시점 재고 예약(선택·후속 F7) |
| 네비 **재고** 메뉴: 잔량 목록 + 이력 조회 | 기본 `wms_prd.md` 수정 |
| 초기 시드: 센터×SKU당 가용 **1000** + 초기화 이력 | 기존 확정(`90`) 주문의 과거 재고 역산 (1차 생략) |

## 2. 기능 요구사항

### CR-INV-01. 재고 잔량 관리

- 재고 단위는 **센터 × 품목(SKU)** 조합당 1행이다.
- 가용 수량(`qty_on_hand` 등 설계자 명명)은 **0 이상**이다. 음수 불가.

### CR-INV-02. 입고 시 재고 증가

- 입고 주문 상태가 **검수완료→입고확정** (`20→90`)으로 전이될 때, **동일 트랜잭션**에서 라인별 수량을 재고에 **가산**한다.
- 반영 수량(1차): 라인의 `inspected_qty`가 0보다 크면 그 값, 아니면 `order_qty` (또는 확정 시 `inspected_qty`를 주문수량과 동일하게 맞춘 뒤 반영 — 설계에서 하나로 확정).
- 해당 센터×SKU 재고 행이 없으면 생성 후 가산한다.
- 증감 **이력**을 남긴다 (유형: 입고 반영).

### CR-INV-03. 출고 시 재고 감소

- 출고 주문 상태가 **피킹완료→출고확정** (`20→90`)으로 전이될 때, **동일 트랜잭션**에서 라인별 수량을 재고에서 **차감**한다.
- 반영 수량(1차): 라인의 `picked_qty`가 0보다 크면 그 값, 아니면 `order_qty`.
- 가용 재고가 부족하면 **전이 전체 롤백**, HTTP 400 및 명확한 메시지.
- 감소 **이력**을 남긴다 (유형: 출고 반영).

### CR-INV-04. 재고 메뉴 (잔량·이력)

- 상단 네비에 **재고** 항목을 추가한다 (`#/inventory` 권장). 대시보드·입고·출고와 동일 레벨.
- **잔량 화면**: 센터·SKU 필터, 센터명·품목명·가용 수량 목록. 행 클릭 시 상세(현재 수량 + 최근 이력).
- **이력**: 목록 또는 상세/탭에서 유형·변동수량·반영후잔량·참조 주문번호·일시·처리자 조회. 센터·SKU·기간·주문번호 필터(Should).

### CR-INV-05. 기본 재고 1000

- 마이그레이션(또는 시드) 적용 시, **활성 센터 × 활성 품목** 모든 조합에 대해 가용 재고를 **1000**으로 생성한다.
- 예: 센터 `CTR01`·`CTR02`, SKU `SKU-AAA`·`SKU-BBB`·`SKU-CCC` → **6행**, 각 1000.
- 초기화는 이력에 유형 **초기재고**(또는 `INIT`)로 남겨 “왜 1000인지” 추적 가능하게 한다 (Should: Must에 가깝게 권장).
- 이후 입고/출고 확정분만 증감한다. **이미 확정된 과거 시드 주문은 재고에 역반영하지 않는다.**

### CR-INV-06. 회귀

- 입고·출고 목록/상세/등록/전이(재고 부족이 아닌 정상 경로), 대시보드가 동작해야 한다.
- 재고 부족 출고 확정만 실패하고, 허용 전이·이력이 깨지지 않아야 한다.

## 3. 데이터 요구사항

테이블·컬럼 물리명은 설계자가 `06-database.mdc`에 맞춘다. 개념 요구만 제시한다.

| ID | 요구 |
|----|------|
| D-1 | 재고 잔량: 센터×SKU UK, 가용 수량 ≥ 0, 공통 감사 컬럼·COMMENT |
| D-2 | 재고 이력: 유형, 변동 수량(±), 반영 후 잔량, 센터·SKU(또는 잔량 FK), 참조 `order_kind`+`order_no`(및 라인 선택), 처리자·일시 |
| D-3 | 거래 유형 공통코드 예: `INBOUND`(입고 반영), `OUTBOUND`(출고 반영), `INIT`(초기재고) |
| D-4 | 기준 DDL은 migration으로 추가·동기화. `std_check` PASS |
| D-5 | 초기 데이터: 활성 센터×활성 품목마다 qty=1000 + INIT 이력 |

기존 `inbound_order` / `outbound_order` 헤더·라인 스키마는 **컬럼 추가 없이** 연동한다.

## 6. 인수 기준 (Acceptance)

1. DB에 재고 잔량·이력이 있고, 활성 센터×SKU마다 초기 가용 **1000**이다.
2. 입고 확정(`20→90`) 후 해당 센터·SKU 재고가 라인 수량만큼 **증가**하고 이력이 남는다.
3. 출고 확정(`20→90`) 후 재고가 **감소**하고 이력이 남는다. 부족 시 확정 실패·메시지.
4. 네비 **재고**에서 잔량 목록과 이력을 확인할 수 있다.
5. 기존 입고·출고·대시보드·등록 기능이 정상 동작한다(부족 출고 확정 제외).
