## 1. 배경 및 목적

### 1.1 운영 요청 (원문)

> (물류센터 운영) 출고도 시드만으로는 연습이 안 됩니다.  
> **출고 등록**을 할 수 있게 해 주세요.  
> 버튼은 **대시보드·입고·출고 어디서든** 누를 수 있어야 하고,  
> 등록 화면은 **출고 주문 상세를 보는 것과 비슷한 형태**면 좋겠습니다.

### 1.2 As-Is

| 영역 | 현재 | 문제 |
|------|------|------|
| 데이터 | `outbound_order` / 라인은 시드·조회·전이만 | 화면에서 신규 출고 주문을 만들 수 없음 |
| API | `GET` 목록·상세, `POST .../transition`만 존재 | `POST /api/outbound/orders` 등록 API 없음 |
| UI | 전역 **입고 등록**은 있을 수 있으나 **출고 등록** 진입점 없음 | 출고만 시드 의존 |
| 상세 | `OutboundDetail`는 조회·전이 전용 | 동일 레이아웃의 **입력(등록)** 모드가 없음 |

### 1.3 To-Be

운영자가 어느 화면(대시보드·입고·출고)에 있어도 **[출고 등록]**으로 들어가,  
**출고 주문 상세와 유사한 다이얼로그**에서 헤더·라인을 입력해 주문을 생성한다.  
생성 직후 상태는 `00`(주문생성)이며, 이후 처리는 기존 F2 전이 흐름을 그대로 사용한다.

### 1.4 범위

| 포함 | 제외 |
|------|------|
| 출고 주문 헤더+라인 **신규 등록** API·화면 | 재고 가용 검증·재고 차감 (F6·F7 본문 — 후속) |
| 상단 네비에 **[출고 등록]** — 대시보드·입고·출고 **모든 라우트**에서 노출 | 마스터(센터·품목) CRUD 화면 |
| 등록 UI = **출고 상세와 같은 구성**(헤더 그리드 + 라인 테이블 + 하단 액션) | 등록 시 피킹수량 편집 (1차: `picked_qty = 0`) |
| 담당자 이름·연락처 입력 (기존 컬럼 사용) | 기본 `wms_prd.md` 수정, 입고 등록 PRD 재정의 |
| 서버 주문번호 자동 채번 | 인증·외부 ERP 수신 |

입고 등록 버튼과 **병존**한다. 서로 대체하지 않는다.

## 2. 기능 요구사항

### CR-F2-21. 전역 [출고 등록] 진입

- 상단 네비게이션 영역(앱 공통 헤더)에 **[출고 등록]** 버튼을 둔다.
- `#/dashboard`, `#/inbound`, `#/outbound` **어느 화면에 있어도** 동일 버튼이 보이고 동일 등록 UI를 연다.
- 네비의 「대시보드 / 입고 / 출고」 및 (있으면) **[입고 등록]**과 **함께** 쓰이며, 특정 목록 전용 버튼만으로 대체하지 않는다. (목록 보조 버튼 추가는 허용)

### CR-F2-22. 등록 UI = 출고 상세 형태

- 등록 화면(권장: `el-dialog`)의 레이아웃은 기존 **출고 주문 상세**와 대응한다.

| 상세(조회) 영역 | 등록(입력) 대응 |
|-----------------|-----------------|
| 주문번호 | 자동 채번 예정 안내 또는 저장 후 표시 (입력 불가) |
| 센터 | 센터 선택 (`el-select`, 시드 센터) |
| 상태 | 고정 표시: `00` 주문생성 |
| 주문일시 | 서버 `now()` (Should: 기본 now) |
| 담당자 이름·연락처 | 텍스트 입력 (NULL 허용) |
| 라인 테이블 | SKU·주문수량 입력 행. 라인 추가/삭제. **피킹수량은 0** 읽기 전용(또는 숨김) |
| 전이 버튼 | 없음. 대신 **[저장(등록)]** / **[취소]** |

- 폭·그리드(2열)·라인 테이블 느낌은 `OutboundDetail`과 맞춘다. **동일 정보 구조**가 Must이다.

### CR-F2-23. 출고 주문 생성 규칙

- 저장 시 `status_code = '00'`.
- `order_no`는 서버가 발급한다. 권장 형식: `OB-{center_no}-{일련}` (기존 시드·`OB-DONE` 등과 충돌하지 않게 일련 관리).
- 센터·SKU는 마스터에 존재하고 `is_active = true`여야 한다.
- 라인 1건 이상, 각 `order_qty` > 0 (정수).
- `picked_qty` 초기값 0.
- 헤더·라인은 **동일 트랜잭션**으로 저장한다.
- **1차:** 등록 시 재고 수량 검증은 하지 않는다. (재고 연동은 `wms_prd-inventory-flow.md` F7 후속)

### CR-F2-24. 등록 성공 후

- 성공 토스트 후 다이얼로그를 닫는다.
- 현재 라우트가 `#/outbound`이면 목록을 새로고침한다.
- 다른 라우트에서는 닫기만 해도 되고, Should로 「출고 목록으로 이동」 또는 방금 만든 주문 상세 오픈을 제공한다.
- 등록된 주문은 기존 F2 상세·전이로 이어서 처리한다.

### CR-F2-25. 회귀

- 기존 출고 목록·상세·전이, 입고(등록·조회·전이), 대시보드, 담당자 표시는 깨지지 않아야 한다.

## 4. API·화면 영향 (초안)

### 4.1 API

| 구분 | 내용 |
|------|------|
| 신규 | `POST /api/outbound/orders` — 출고 주문 등록 |
| 기존 | `GET /api/outbound/orders`, `GET .../{orderNo}`, `POST .../transition` — 변경 최소화 |

**요청 Body 초안** (snake_case)

```json
{
  "center_no": "CTR01",
  "partner_contact_name": "한도윤",
  "partner_contact_tel": "010-6666-2001",
  "created_by": "demo-user",
  "lines": [
    { "sku_no": "SKU-AAA", "order_qty": 10 },
    { "sku_no": "SKU-BBB", "order_qty": 5 }
  ]
}
```

**성공 응답 초안**: `{ "success": true, "data": { ...상세와 동일 헤더+lines, status_code "00"... } }`  
**실패**: `{ "success": false, "message": "..." }` (검증 실패 400 권장)

## 6. 인수 기준 (Acceptance)

1. 대시보드·입고·출고 **각 화면**에서 **[출고 등록]**을 눌러 동일 등록 UI가 열린다.
2. 등록 UI가 출고 상세와 같이 **헤더 영역 + 라인 테이블 + 하단 액션** 구조이다.
3. 유효한 센터·SKU·수량으로 저장하면 `order_no`가 발급되고 상태 `00`인 주문이 DB·목록에 보인다.
4. 담당자 이름·연락처를 넣으면 상세·목록에 표시된다.
5. 잘못된 센터/SKU/수량 0/라인 없음은 등록되지 않고 메시지가 나온다.
6. 기존 출고 전이·입고·대시보드·(있으면) 입고 등록이 동작한다.
