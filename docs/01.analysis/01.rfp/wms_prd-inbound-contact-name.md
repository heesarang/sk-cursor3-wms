## 1. 배경 및 목적

### 1.1 운영 요청 (원문)

> (물류센터 운영) 지난번에 연락처는 넣어 주셨는데, 번호만으로는 누구인지 구분이 안 됩니다.  
> 같은 거래처인데 담당자가 바뀌면 이름도 같이 보고 싶습니다.  
> 입고 오더에 담당자 이름도 목록·상세에 표시해 주세요.

### 1.2 As-Is

| 영역 | 현재 | 문제 |
|------|------|------|
| 데이터 | 연락처(`partner_contact_tel` 등)만 있거나 예정 | 번호만으로는 담당자 식별 불가 |
| 업무 | 동일 거래처에서 담당자가 교체됨 | 이름 없이 전화하면 잘못된 상대·재확인 비용 발생 |
| 화면 | 목록·상세에 이름 미표시 | 연락처와 이름을 한눈에 대조할 수 없음 |

선행 PRD(`wms_prd-inbound-contact-tel`)로 연락처 표시가 목표이나, **이름 필드는 포함하지 않았다.**

### 1.3 To-Be

입고 주문 단위로 **거래처 담당자 이름**을 연락처와 함께 보관·표시한다.  
운영자는 목록·상세에서 **이름 + 연락처**를 보고 담당자를 구분한 뒤 연락할 수 있어야 한다.

### 1.4 범위

| 포함 | 제외 |
|------|------|
| 입고 주문(`inbound_order`)에 담당자 이름 컬럼 추가 | 거래처·담당자 마스터 테이블·이력 관리 |
| 입고 목록·상세 API 응답에 이름 포함 | 출고 주문 담당자 이름 |
| 입고 목록·상세 UI에 이름 표시 (연락처와 인접 배치 권장) | 이름/연락처 수정 전용 화면 (조회 Must, 입력은 시드·후속) |
| 마이그레이션 + 기준 DDL·데이터 사전 동기화 | 연락처 PRD 범위의 재정의(연락처 컬럼 자체는 선행 문서 따름) |

기준 DDL은 `database/migrations/`에 ALTER를 남긴 뒤 기준 DDL·사전을 맞춘다. 선행 연락처 마이그레이션과 **별도 마이그레이션 파일**로 추가하는 것을 권장한다.

## 2. 기능 요구사항

### CR-F1-11. 입고 주문에 담당자 이름 보관

- 입고 주문 헤더에 거래처 담당자 이름을 저장할 수 있어야 한다.
- 기존 주문·연락처만 있는 행을 고려해 **NULL 허용**이다.

### CR-F1-12. 입고 목록에서 이름 표시

- 입고 주문 목록에서 각 행의 담당자 이름을 확인할 수 있어야 한다.
- 값이 없으면 빈 값 또는 `-` 표시로 충분하다.
- 가능하면 연락처 컬럼과 나란히 두어 이름·번호를 함께 본다.

### CR-F1-13. 입고 상세에서 이름 표시

- 입고 주문 상세에서 담당자 이름을 확인할 수 있어야 한다.
- 연락처와 함께 표시하는 것을 Should로 한다.

### CR-F1-14. 기존·선행 기능 회귀 유지

- 연락처 표시(선행 변경), 센터·상태 필터, 상태 전이는 기존과 동일하게 동작해야 한다.
- 대시보드·출고는 본 변경으로 깨지지 않아야 한다.

## 3. 데이터 요구사항

물리 컬럼명은 설계자가 `06-database.mdc`에 맞춰 정한다. 아래는 **예시(권장)**이다.

| 항목 | 값 |
|------|------|
| 대상 테이블 | `wms.inbound_order` |
| 컬럼(예시) | `partner_contact_name` |
| 타입 | `VARCHAR(100)` |
| NULL | 허용 (`NULL`) |
| 기본값 | 없음 |
| COMMENT(예시) | `거래처 담당자 이름 (예: 홍길동)` |
| 위치 | **공통 감사 컬럼 뒤**, 연락처 컬럼이 있으면 그 **뒤(또는 인접)** 에 추가 |

**비고**

- 담당자 마스터를 신설하지 않는다. 이름은 입고 주문 **스냅샷 속성**이다.
- 담당자 교체 시 “과거 주문에 찍힌 이름”이 당시 담당자를 남기는 것이 의도다 (이력 테이블 불필요).
- 연락처 컬럼명과 접두를 맞추면(`partner_contact_name` / `partner_contact_tel`) 가독성에 유리하다.

## 4. API·화면 영향 (초안)

| 구분 | 영향 |
|------|------|
| API | `GET /api/inbound/orders`, `GET /api/inbound/orders/{orderNo}` 응답에 이름 필드 추가 (snake_case) |
| 전이 API | 변경 없음 |
| UI | 입고 목록 컬럼·상세 헤더에 담당자 이름 표시 (연락처 옆 권장) |
| Mapper/XML | 입고 목록·상세 SELECT에 컬럼 포함 |
| DB | `migrations/YYYYMMDD_NNN_add_*_name_to_inbound_order.sql` + `wms_ddl.sql` + `data-dictionary.md` |

상세 JSON은 `REQ-F1-inbound.md` §5 갱신에서 확정한다.

| 구분 | 요구 |
|------|------|
| 변경 관리 | DB 직접 ALTER 금지. 마이그레이션 파일 작성 후 승인·적용 |

## 6. 인수 기준 (Acceptance)

1. DB: `inbound_order`에 담당자 이름 컬럼과 COMMENT가 있다.
2. API: 입고 목록·상세 JSON에 이름 필드가 포함된다 (값 또는 null).
3. UI: 입고 목록·상세에서 담당자 이름을 확인할 수 있다.
4. 회귀: 연락처 표시·입고 상태 전이·대시보드가 동작한다.
5. 산출물: 마이그레이션 + 기준 DDL + 데이터 사전이 일치한다.
