# CR 검증 (`/my-cr-verify`)

## 사전 조건

- 영향 문서 경로를 알고 있을 것 (승인된 IMPACT 문서)
- `/my-cr-app`까지 끝난 상태를 전제로 한다

## 프리플라이트

- `GET` health 또는 `/v3/api-docs` (또는 동등)로 서버 생존 확인  
- 실패 시 **코드를 더 고치지 말고** 환경 문제로 보고 후 중단

## 검증 (기본 = 비파괴)

**8a 기본 (승인 없이 수행)**

1. 입고 목록·상세 응답에 새 필드 키 존재 (null 허용)
2. (가능하면) 화면/문서 기준으로 표시 경로 확인
3. 대시보드 summary 조회 스모크
4. 불허 전이 1건 (예: 확정 주문 재전이) → 400 기대 — 데이터 상태 유지

**8b 선택 (추가 승인 필요)**

채팅에 `회귀 전이 승인: <order_no>` 가 있을 때만 정상 전이 스모크 수행.  
없으면 8b를 건너뛴다.

## 대조표 (필수)

영향 문서 ALLOWED_PATHS vs 이번 CR에서 실제로 수정된 파일 표:

| 경로 | 허용 | 실제 수정 | 결과 |
|------|------|-----------|------|
| ... | Y/N | Y/N | OK / 범위위반 |

범위 위반이 있으면 명시하고, 가능하면 되돌리기 제안만 한다 (임의 대량 revert 금지).

## 완료 리포트 플래그

- `files_synced` — migration·DDL·사전
- `db_applied` — 본인 DB 적용 여부
- `app_verified` — API/화면 필드 확인
- `regression_ok` — 8a (및 승인된 8b)

## 종료

```
## /my-cr-verify 완료 — 체인 종료
- files_synced / db_applied / app_verified / regression_ok: ...
- 커밋·push는 사용자가 요청할 때만 (/git-commit 등)
```

다음 CR이 있으면 `/my-cr-plan`부터 새로 시작한다.
